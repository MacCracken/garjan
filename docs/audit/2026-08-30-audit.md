# Security & correctness audit — 2026-08-30

Covers garjan **2.0.1 → 2.0.4**. Findings were fixed across 2.0.2 (security),
2.0.3 (allocation hardening) and 2.0.4 (arena lifetime).

**Scope**: all 33 modules of `src/` (7,502 lines), cross-checked against the
frozen Rust oracle at `rust-old/src` (8,395 lines), plus the vendored
dependency bundles where garjan's contract with them was in question.

**Method**: seven independent lenses — memory safety, input validation,
deserialization, parity vs the oracle (foundations, and weather/water/surf
separately), general correctness, and per-sample optimization. Every candidate
finding then faced two independent adversarial reviewers, one instructed to
*refute* it and one to establish its true reachability. **34 findings were
judged; 17 survived, 17 were refuted.** The refuted ones are listed below,
because "we checked and it was fine" is worth recording.

---

## Confirmed and fixed

### 1. `*_from_json_str` discarded `*_build_naad`'s error code — 20 of 21 sites

**Severity: P1 (crash from untrusted input).** Fixed in 2.0.2.

The `*_new` path always checked it; the deserialize path called it bare.
`*_build_naad` returns *before* assigning the naad component pointers when a
constructor rejects its input, and `*_from_json_str` never validated the
JSON-supplied `sample_rate` the way `*_new` does. A well-formed document with
`"sample_rate":0.0` therefore returned a **non-negative pointer** whose
component fields were still 0 — the caller's `garjan_is_err` check passed, and
the first `process_block` dereferenced null.

Reproduced against 2.0.1 as a **SIGSEGV (exit 139)** and re-confirmed as a
clean `GARJAN_ERR_SYNTHESIS_FAILED` after the fix. `foliage` was the single
site already written correctly. Regression test: `tests/fire.tcyr`.

### 2. `voice_pool_from_json_str` sized the pool from `max_voices`

**Severity: P1 (memory exhaustion from untrusted input).** Fixed in 2.0.2.

Rust derives `Deserialize` on `slots: Vec<VoiceSlot>`, so serde allocates
exactly as many slots as the array carries and never calls `VoicePool::new`.
The port passed the raw `max_voices` scalar into `voice_pool_new`, whose loop
allocates one `VoiceSlot` per unit against an arena that never frees — so
`{"max_voices":2000000000,"slots":[]}`, about 40 bytes, exhausted memory.
Now bounded by the array length, which is a no-op on any well-formed
round-trip and restores parity with Rust. Regression test: `tests/voice.tcyr`.

### 3. `insect_from_json_str` dropped the 1..8 `swarm_count` clamp

**Severity: P1 (unbounded CPU from untrusted input).** Fixed in 2.0.2.

Every other path enforces that invariant and the eight `det0..det7` fields
physically encode it. `swarm_count` bounds the per-sample inner voice loop, so
an unclamped value made one `process_block` effectively unbounded — with
`insect_detune` saturating every index >= 7 to `det7` instead of trapping, so
nothing downstream noticed. Regression test: `tests/insect.tcyr`.

### 4. A failed allocation was indistinguishable from success

**Severity: P1 (null-pointer write under memory pressure).** Fixed in 2.0.3.

`alloc` reports exhaustion by returning `0`; `garjan_is_err` treats only
`< 0` as an error; and `GARJAN_OK` **is** `0`. So `garjan_is_err(alloc(n))` was
`0` on failure and every check passed. Constructors write through their
allocation on the very next line, making OOM a store to address 0.

All 85 direct sites plus ~70 consumers of pointer-returning helpers
(`rng_new`, `garjan_dcblocker_new`, `voice_slot_new`, `modal_modespec_new`,
`exciter_new`, the `*_config` builders) now route through `garjan_alloc`, which
maps `0` to the new `GARJAN_ERR_ALLOCATION`. 132 guards. The decision to return
an error rather than abort — Rust aborts on OOM — is
[ADR-0005](../adr/0005-allocation-failure-is-an-error-code-not-an-abort.md).

**Invariant to keep**: `src/*.cyr` contains no raw `alloc(` outside
`garjan_alloc` itself.

### 5. Two streaming paths grew the arena on every block

**Severity: P2 (unbounded growth in long-running use).** Fixed in 2.0.4.

`impact_generate` built a fresh `Exciter` + `Rng` per call (64 B/block) and
`texture_process_block` allocated a 24-byte band-mix buffer per block. Both
were *faithful* ports — Rust allocated per call too — but Rust dropped the
values and the arena does not. Measured over 200 blocks: **12,800 → 0** and
**4,800 → 0** bytes. That was ~27 MB/hour combined, reaching the 2 GiB
`ALLOC_MAX` in about three days of continuous streaming.

### 6. `cyrius fmt --check` false-negatives

**Severity: P3 (broken release gate).** Fixed in 2.0.2.

`--check` reported `src/builder.cyr` clean while the formatter itself rewrote
20 lines of it, which is what made `cyrius audit` fail its fmt gate. **Verify
formatting by running the formatter into a scratch copy and diffing, not by
trusting `--check`.**

## Confirmed, not fixed — recorded instead

- **No upper bound on `duration` / `sample_rate`.** `validate_duration` accepts
  any positive finite value, so 1e8 s sizes a 4.4-trillion-sample buffer. This
  is *faithful* to the oracle (`rust-old/src/dsp.rs:39` validated only
  positive-and-finite), so capping is a deliberate divergence needing an ADR.
  Scheduled 2.2.x.
- **Deserialize does not restore DSP state, and Rust's did.** See
  [architecture note 001](../architecture/001-deserialize-does-not-restore-dsp-state.md).
  Source comments claiming a `#[serde(skip)]` mirror were citing an attribute
  that does not exist in `rust-old`. Scheduled 2.2.x; it changes the JSON format.
- **Out-of-range enum ids are absorbed silently.** Rust's exhaustive `match`
  became `if/elif` chains whose final `else` yields the last variant's table
  rather than an error. Scheduled 2.2.x.
- **The arena never frees at all.** `alloc_reset()` invalidates *every*
  outstanding pointer, so it is only usable at a clean epoch boundary. A caller
  constructing and discarding synths in a loop still grows memory. Needs an
  ownership model — 3.0.0.

## Refuted

17 of 34 findings did not survive review. Recorded so they are not re-raised:

- **Undersized stack buffers.** None exist — `src/` declares **zero**
  `var buf[N]` stack arrays, so that entire bug class (where `N` is bytes, not
  entries) is structurally absent from garjan's own code.
- **Symbol collisions with the dependency bundles.** garjan's 399 top-level
  `fn`/`var` symbols intersect naad, hisab, goonj, sakshi, bayan, ganita and
  math at **zero**, in all directions. This mattered because Cyrius emits no
  diagnostic for a duplicate top-level `var` — it shadows silently.
- **API drift across the 2.0.1 dependency bump.** Every library function
  garjan calls was compared old-bundle vs new: no arity changes, nothing
  removed.
- **`filter_biquad_new` constant renaming changing behavior.** naad's
  `FILTER_*` → `NAAD_FILTER_*` rename was verified value-for-value: both
  bundles define the eight modes as 0-7 in the same order, so no filter changed
  type or response.
- **Several proposed "redundant second DC-blocking pass" merges.** Only `wind`
  and `texture` write each index exactly once; the other ten accumulate (fire
  adds crackle over roar, rain adds drops), so their pass genuinely must come
  last. Merging those would have changed the audio.
- The remainder were misreadings of Cyrius idioms — chiefly error-code-versus-
  pointer returns, and byte-versus-slot offsets in `load64`/`store64`.

## Notes on method

Two things were worth more than any single finding:

1. **The test suite does not verify sample values.** It asserts finiteness,
   energy and serde round-trips. Every optimization in 2.0.5 would have passed
   it while silently altering the audio. `scripts/audio-hash.cyr` exists to
   close that gap and must stay bit-identical across performance work.
2. **`cyrius build` does not regenerate `dist/`.** `src/main.cyr` includes the
   bundle, so a build after editing `src/` compiles the STALE bundle and still
   reports `OK`. During this audit that briefly made a fix look ineffective when
   it was simply not compiled. Always `cyrius distlib` after a source edit;
   `cyrius distlib --check` reports staleness correctly.
