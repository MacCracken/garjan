# Audit sweep — 2.5.1

Second full sweep, covering everything added since the
[2.0.2 audit](2026-08-30-audit.md): the allocation guard (2.0.3), arena
lifetime (2.0.4), hot-path optimization (2.0.5, 2.3.0), the integration suite
and benchmarks (2.1.0), enum-id validation (2.2.0), the size caps (2.4.0) and
serde live-state transfer (2.5.0).

**Method**: mechanical invariant checks over the whole tree, then targeted
hostile-input testing against the newest and largest attack surface — 2.5.0's
`"dsp"` loaders, which parse untrusted JSON and write into vectors.

**Result: 3 defects found and fixed, 1 hardening change.** All three share a
root cause, and it is the same one the 2.0.2 audit found: **the deserialize
path does not enforce what the constructor enforces.**

---

## 1. `*_from_json_str` never validated `sample_rate`

**Severity: P1 (accepts hostile input the constructor rejects).**

Zero of the 21 deserialize entry points validated the JSON-supplied
`sample_rate`. The 2.0.2 fix made them propagate `*_build_naad`'s error, which
*looked* like validation because most `build_naad`s construct a naad component
that rejects a bad rate.

`bubble_build_naad` does not — it only calls `noise_new`, which cannot fail.
So `bubble_from_json_str` with `"sample_rate":0.0` **constructed successfully**,
stored 0, and `bubble_synthesize` then returned an **empty buffer** with no
error. A caller sees a valid object that silently produces nothing.

Fixed by validating `sample_rate` directly in all 21, exactly as `*_new` does.
Relying on a downstream component to validate was the design error; one synth
happened not to have such a component.

## 2. `*_from_json_str` never re-validated enum ids

**Severity: P1 (bypasses ADR-0006 from untrusted input).**

2.2.0 rejected out-of-range enum ids at 21 constructors and 10 dispatchers —
but not on the deserialize path. `bubble_new(99, sr)` was rejected while
`bubble_from_json_str` with `"bubble_type":99` was **accepted and stored 99**,
reaching exactly the silent wrong-table behaviour
[ADR-0006](../adr/0006-out-of-range-enum-ids-are-rejected.md) exists to prevent.

Fixed: every restored enum id is now checked with `garjan_enum_invalid` against
the same named bound the constructor uses — 26 ids across 18 synths.

## 3. `impact_synthesize_velocity` had no sample-count guard

**Severity: P2 (unbounded allocation).**

2.4.0 applied `garjan_validate_sample_count` at 20 sites via a pattern match on
`f64_mul(<Type>_sample_rate(self), duration)`. `impact_synthesize_velocity`
computes it with the **operands reversed** — `f64_mul(duration, sample_rate)` —
so the rollout skipped it silently. 21 of 21 guarded now.

A scripted rollout is only as good as its pattern; the check that caught this
was "every function that builds a vector must have the guard", not "every match
of the pattern was rewritten".

## 4. Hardening: insect stack buffers had zero margin

`insect_process_block` indexes two 64-byte stack buffers (8 f64 slots) by
`swarm_count`. All three writers of `swarm_count` clamp to 1..8, so this was
correct — but with **no margin at all**, and a future cap raised without
resizing the buffers would corrupt the stack silently. Now bounded at the point
of use as defence in depth.

---

## Verified clean

- **The 2.5.0 `"dsp"` loaders are robust.** Twelve hostile documents — `dsp` as
  null/number/string/array, component values wrong-typed, empty arrays,
  arrays of objects, a 40-element octave array against a 16-slot vector,
  truncated arrays, malformed JSON — produce no crash and no non-finite output.
  bayan's tag checks plus the loaders' length guards hold.
- **ADR-0005 invariant**: no raw `alloc(` in `src/` outside `garjan_alloc`.
- **No unguarded pointer-returning helper results** (0 of ~160 call sites).
- **Stack buffers**: only 3 in the whole tree, all correctly sized in *bytes*
  (`freqs[64]`/`phases[64]` = 8 slots, `mixbuf[24]` = 3).
- **Runtime setters clamp** — all 8 intensity/velocity/pressure setters, as the
  threat model claims.
- **`process_block` allocates nothing** on 20 of 21 synths. `whistle` remains
  the documented exception (32 B/sample via naad's heap-returning
  `SvfOutput`), blocked on an upstream naad addition.
- Lint 0 warnings, vet clean, 0 lines over 120 chars, formatter-clean across 73
  files, audio bit-identical to 2.5.0.

## Note on method

Every finding here came from checking a *property* over the whole surface —
"does every deserialize entry point validate its sample rate?", "does every
vec-building function have the size guard?" — rather than from re-reading code
that had already been reviewed. The two P1s were invisible to the test suite,
which exercised the constructor path thoroughly and the deserialize path only
with well-formed documents.
