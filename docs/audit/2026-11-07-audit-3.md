# Audit sweep — 2.6.3

Third full sweep, run as a P(-1): find what the test suite cannot. At 2.6.2 all 847
assertions passed while JSON could set states no public call reaches. One of them hangs
`cloth` forever, and others make output non-finite from then on. The suite could not see
this, because it only fed the deserializers documents that garjan had written itself.

**Method**: seven passes, each asking a question the suite does not:

1. **Differential against `rust-old/`.** Four independent audits, one per module
   cluster: weather and fluids, contact and impact, aero and creature, and foundations.
   Each built the Rust oracle from a scratch copy, leaving `rust-old/` untouched, and drove
   matching harnesses on both sides. Results were compared at f32 tolerance, not bit for
   bit.
2. **Line by line against `rust-old/`**, by the same four audits. Each reproduced a defect
   before listing it.
3. **Fault injection.** The harness replaces `alloc` so that it refuses the Nth
   allocation, or every allocation from the Nth on. It does this for every construct,
   load, synthesize and serialize path of all 22 entry points: 9,238 cases, each in its
   own process.
4. **All-zero sweep.** Every public function is called with 0 for every argument. A
   struct handle gets a valid object instead. 620 calls.
5. **Property sweeps** over the whole tree. Does every enum argument in `src/`, `tests/`,
   `scripts/` and `docs/examples/` belong to its enum? Does each of the three copied
   families open the same way?
6. **Independent review** of the merged diff, by a reader who saw none of the work.
7. **Revert proof.** 30 guards were reverted one at a time on a frozen copy of the
   finished tree. Each one must fail a test or the fuzz harness.

**Result: 32 defects fixed, 2 ADRs, 5 upstream items to file.** 23 are in garjan's code:
11 on the deserialize path, 6 on the API and 6 on the allocation path. 3 are in the tests
and the fuzz harness, and 6 are documentation or gate defects found in review. Every code
fix has a test,
and each test was shown to fail without its fix. All 21 audio hashes match 2.6.2. One
deliberate exception, water's Stream LFO outside intensity 0..1, is recorded in
[ADR-0011](../adr/0011-water-stream-lfo-follows-the-raw-intensity.md).

The root cause repeats the one the
[2.0.2](2026-08-30-audit.md) and [2.5.1](2026-08-30-audit-2.md) sweeps found, one
level down. Those sweeps made the deserializer check what the constructor checks. This
one makes it refuse **any state the API cannot produce**. That rule is now
[ADR-0010](../adr/0010-a-document-restores-only-states-the-api-can-produce.md).

## 1. The deserialize path (ADR-0010)

| # | Defect | Severity | Fix |
|---|---|---|---|
| D1 | **An even PCG increment hangs synthesis.** `rng_inc` restored as any integer. With an increment divisible by 4 some states are fixed points. The aero audit's `cloth` document lands on one whose draw is `0xFFFFFFFF`, so `rng_poisson` never returns. `rust-old` hangs on the same document. | P1, hang | `rng_restore` refuses an even increment at all 23 restores, the exciter's included |
| D2 | **A NaN or infinite value in `"dsp"` filter memory** made output non-finite for the rest of the synth's life. Found by both the foundation and weather audits. | P1 | every `"dsp"` loader refuses non-finite values |
| D3 | **A zero xorshift state** in an LFO or noise generator is a fixed point, so the generator is stuck. | P2 | refused |
| D4 | **Fields that were unsigned or `bool` in Rust restored signed.** A negative `sample_position` made output non-finite for good, and an `active` of 2 was accepted. 13 unsigned keys and 5 bool keys, plus the exciter's position and active flag. | P1 | `garjan_json_open` refuses a negative value or a float in an unsigned key, and anything but 0 or 1 in a bool key |
| D5 | **Voice slots outside their Rust types**: `active` 2, priority 256, a negative age, a tag above 2^32. | P2 | refused on load |
| D6 | **The constructor's clamps were skipped on load.** Thunder's distance, wind's speed and gustiness, foliage's wind speed and contact intensity, and 17 more. An unclamped value made the work per event grow with the value, quadratically in places. | P2, run time | the same 22 clamps on load |
| D7 | **Derived fields trusted from the document.** bubble's decay time and event rate, precipitation's `decay_samples` and foliage's event length set the work per event. One document cost hours of CPU at the 600 s cap. | P1, run time | re-derived from type and sample rate on load |
| D8 | **A failed tree parse was silent.** A document the tree parser refuses but the field reader accepts loaded without its live state, and no error was reported. This was the roadmap's first open question. | P2 | refused |
| D9 | **A `"dsp"` that is not an object, or a `"slots"` that is not an array,** loaded without its live state. | P2 | refused |
| D10 | **`null`, a string or a bool for a number** restored as NaN or as garbage. `null` was the ADR-0009 path. | P2 | refused |
| D11 | **`1e999` restored as +Inf.** | P2 | refused, as serde refused it |

serde's types refuse D2, D4, D5, D10 and D11, so refusing them restores Rust's behaviour.
D1, D3, D6 and D7 load in `rust-old` too. Refusing or re-clamping them diverges on
purpose, and ADR-0010 records that. D8 and D9 have no Rust counterpart.

## 3. Allocation failure (ADR-0005)

Fault injection tested ADR-0005's promise end to end for the first time. Nothing had done
so before.

| # | Defect | Fix |
|---|---|---|
| F1 | Unchecked `vec_new` in `voice_pool_new`, `generate_modes` and `modal_bank_new`, and unchecked `str_builder_new` in all 21 serializers. A refused allocation faulted later in `vec_push` or the builder. | checked |
| F2 | Seventy-two `"dsp"` puts and 6 state emitters handed bayan a null node. | `garjan_dsp_put` and the emitters check every node |
| F3 | `modal_bank_new`'s allocation failure surfaced as `SYNTHESIS_FAILED`, and impact's restore did not check `material_properties_new`. | propagated; checked |
| F4 | `garjan_vec_zeros(n)` computed `n * 8` unchecked, which wraps from n = 2^61. Every caller bounds `n`, so it was latent. | bounded at the helper |
| F5 | `garjan_emit_with_dsp` faulted on an empty params builder. No public path passes one. | refused |
| F6 | All 28 `noise_new` results were stored unchecked. naad 2.3.3 cannot return a failure today: it faults first (U1 below). With naad's constructors made null-safe in the harness, the next refused allocation reached garjan as a component pointer. | `garjan_noise_new`; `tests/naad_failure.tcyr` |

| Sweep | Segfaults | Aborts |
|---|---:|---:|
| Before the fixes, real naad | 1,945 | 461 |
| Before the fixes, null-safe naad stand-ins | 1,398 | 461 |
| After the fixes, stand-ins | **380** | **274** |

The final sweep is 9,238 cases, and 8,584 of them end cleanly, with an error code or a
successful result.

Every remaining segfault was traced to its faulting function under gdb. **None is in
garjan's code**:

| Item | Where | What |
|---|---|---|
| U1 | naad | `noise_new`, `filter_biquad_with_gain`, `filter_svf_new` and `modulation_lfo_new` write through a refused allocation |
| U1b | naad | `naad_vec_zeros` does not check `vec_new` |
| U2 | cyrius | the `#derive(Serialize)` reader memsets a refused allocation |
| U3 | stdlib, bayan | `str_builder` and bayan's builder exit the process on a refused allocation. Some growth paths fault before they get there |
| U4 | bayan | `bayan_json_v_obj_set` stores a null pair when its pair allocation is refused, and the builder then faults on it |

The aborts are U3, and they are by design upstream. A host that runs out of memory while
serializing can therefore be terminated. The threat model now says so, where it used to
claim "no panics or aborts".

## 5. Review

The independent reviewer confirmed seven findings. All seven are fixed or recorded:

- **T2 and T3** are above.
- **`cyrius audit` exited 1.** The new code had 16 long lines and 5 files the formatter
  would rewrite, and a helper had landed under `main`'s doc comment.
- **ADR-0010 claimed that water's output did not move.** It does, for Stream outside
  0..1. ADR-0011 now records it.
- **ADR-0010 claimed that every document garjan writes still loads.** A NaN stored
  through the API is written as `null` and is now refused. The sentence is qualified.
- **The strictness claim depends on the toolchain.** Duplicate keys and leading zeros are
  refused from bayan 1.11. Under dhvani's cyrius 6.6.10 both load, and both copies of a
  duplicate key are still checked. The comment and the ADR now say so.
- **A stale comment on `garjan_vec_zeros`** is fixed.

The reviewer also questioned `rng_restore`'s comment, which said an even increment
always gives a fixed point that draws `0xFFFFFFFF`. The arithmetic shows a fixed point
exists only when the increment is divisible by 4, and the draw there depends on the
state. The comment is corrected.

The reviewer's independent checks agree with the gates below. 1,078 synth states (every
type and variant, at 8, 44.1 and 192 kHz, serialized after 1 and 7 blocks) give
bit-identical audio and identical documents. Every 2.6.2 document loads and continues
bit-identically. dhvani's `tests/environment.tcyr` passes 10 of 10 under its own pins.

## 6. Revert proof

30 guards were reverted, each in its own copy of the finished tree. On the first run 26
failed a test. The other four were gaps, now closed:

| Guard reverted | Why it was not caught | Now |
|---|---|---|
| The exciter's negative-position check in `"dsp"` | The test edited the top-level `exc_position`, which `garjan_json_open` catches first | a test edits the exciter's live state |
| `garjan_json_open`'s non-finite check | The suite only tried `null`, which is refused as the wrong type | tests for `1e999` and `-1e999` |

30 of 30 are now caught.

## 7. Refactor

- **The three copied families now open through shared helpers.**
  - All 22 `*_from_json_str` start with `garjan_json_open`.
  - All 21 synths' buffers come from `garjan_synth_buffer`; `impact_synthesize`
    delegates to the velocity path, which uses it.
  - All 21 synth serializers check their builder.
  - All 72 `"dsp"` loads and 72 puts are checked through one counter per function.

  Cyrius has no closures or generics, so the field-by-field middles stay per synth. The
  bundle compiles under dhvani's pins, with no 6.7.x syntax and no stdlib call missing
  from 6.6.10.
- **`garjan_dsp_node` is removed.** `garjan_json_open` replaces it.
- **`lib/boxed.cyr`, `lib/callback.cyr` and `lib/tagged.cyr` are removed.** Nothing
  includes them, and `cyrius deps` does not re-create them. The lock drops from 48
  entries to 45.

## 8. Optimization: measured, not adopted

Measured on garjan's build, in nanoseconds per sample: white noise 16, pink noise 79,
biquad 22, SVF step 18, `filter_svf_set_params` 89, `f64_sin` 47.

- **naad's buffer forms.** A synth costs 45 to 700 ns per sample, and it interleaves its
  components per sample with parameters that change per sample. Calling a component over
  a buffer would save a few ns per sample of call overhead, inside the measurement noise.
  Not adopted.
- **`whistle`'s per-sample re-tune.** `filter_svf_set_params` is 89 of about 231 ns per
  sample. `rust-old` does the same. A slower control rate would save about a third, but it
  changes samples, so it is a 2.8.x question and needs an ADR.
- **The smaller synths** (bubble, foliage, precipitation, whoosh, impact) spend their time
  in the same naad building blocks. No garjan-side change saved time measurably while
  keeping output bit-identical.

## 9. Accepted, with reasons

- **A null struct pointer faults.** The zero sweep's three remaining crashes pass 0 for a
  struct or buffer argument: `generate_modes`'s `props`, `modal_bank_process_block`'s
  excitation and `texture_band_mix_into`'s output. garjan checks no handle anywhere, and
  `self` is the same contract. The one helper that should have tolerated a null,
  `garjan_key_is`, now does.
- **Loop counts from the API are not bounded beyond Rust's.** A setter given a huge but
  finite value can make work per event large, as it can in `rust-old`. The threat model
  is malformed data, not a hostile host.
- **ADR-0010's two gaps.** Other stored configuration copies are trusted beyond
  finiteness, and a missing field loads as 0. Both are on the roadmap.
- **NaN stays storable through the API.** ADR-0009 keeps it from hanging, and ADR-0010
  keeps it from coming back through a document.
